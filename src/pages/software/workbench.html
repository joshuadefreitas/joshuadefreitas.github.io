Engineering Workbench

Shows how a codebase is put together and how it changed: the architecture, the dependencies that came and went, and the evidence behind each claim.

Prototype · not yet releasedReads Python, Rust and JavaScriptWritten by me
What it needs
Python 3 and Git. Nothing else.
What it never does
Run the code it is reading.
Every claim has
A file, a line and a commit to point at.
Output
One HTML file that works offline.
01

What changed between two releases, and where?

Pick two snapshots and it ranks where the change concentrates: the packages that gained or lost dependencies, then each dependency with the line that created it.

Every view has a link, so the answer can be sent to someone else.

02

What depends on this, and what would break?

Select a module and the picture reduces to its neighbourhood: dependents in green, dependencies in blue, and the evidence for each edge underneath.

03

Is the architecture still what we meant?

It finds the places where one part of a system reaches into another it shouldn’t, and shows when that import appeared and in which commit.

04

Has anything tangled?

Dependency cycles are flagged when they appear, and again when they are repaired, with the added and removed imports listed by file and line.

How it was checked

I ran it on three open-source projects I didn’t write, and compared its dependency edges with a separate parser written for the purpose, one that never imports the tool’s code.

ProjectDependencies comparedResult
pytest852 import edges across 274 modules850 agree directly; the other two are package re-exports the tool expands on purpose
ripgrep117 crate and module edges (Rust)117 of 117
Express154 file edges (JavaScript)154 of 154

Several bugs showed up this way and were fixed, including Rust restricted-visibility modules and a Cargo manifest parser that invented dependency names. File renames matched git’s own records in all 139 ripgrep and 156 Express cases.

Limits, stated plainly

  • Static reading onlyLexical analysis of imports. It can’t follow imports computed at run time, or code that macros generate.
  • History is sampledEight snapshots, with the most recent 1,200 commits. “When did this dependency appear?” is a bound, not an exact date.
  • Moves are git’s callRenames come from git, with a similarity score. A file moved and heavily edited at once can still look like a deletion and a new file.
  • Three languagesPython, Rust and JavaScript. Everything else is counted but not analyzed.
