How I work

Make the invisible legible.

The hard part is rarely choosing a model in isolation. It is shaping the surrounding system so the result can be trusted, tested, and used.

01Start with the boundary

Define the data contract, the consumer, and the evidence before adding complexity.

02Make behavior observable

Prefer reproducible runs, explicit decisions, and results another person can inspect.

03Earn the abstraction

Keep the first useful system narrow, then deepen it where the work proves the need.

About

Engineering with range.

I’m a data engineer at EY with a background in economics, analytics, and applied modeling. I build systems that connect data, software, and decision-making: structured pipelines, analytical workflows, AI-assisted tools, simulations, and research code that can survive contact with real users.

Outside client work, I use public projects to explore dependable data products, intelligent automation, deterministic simulation, visualization, and the space between research and implementation.
